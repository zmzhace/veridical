# 受限生产配置与运维手册

本轮从 `e8dd138a4269e831e0518db5b55c422ac750676b` 加固。目标不是把演示功能一起暴露到公网，而是提供可单独验收的生产 API。代码验证记录见 [production-verification.md](production-verification.md)，调用流程见 [production-api.md](production-api.md)。

## 1. 支持范围与信任边界

| 项目 | 本配置支持 | 不在本次承诺内 |
|---|---|---|
| 部署 | 单主机、本地持久磁盘；默认最多 2 个并行任务，每租户最多 1 个 | 跨主机共享 SQLite、NFS、自动故障切换、已验证 SLA |
| 流程 | single-loop、stage-gate，严格工具白名单 | supervisor、动态 agent、任意脚本、未审批 fallback |
| 工具 | 内置 echo/finish；代码审查过的只读扩展接口 | 支付、删库、发送消息、写业务系统及其 exactly-once 保证 |
| 回溯 | 事件顺序、调用入参/结果、配置摘要、操作者、任务及构建指纹 | 未记录的模型内部推理、真实模型权重重建 |
| 回放 | 相同运行环境下，成功完成的多轮会话，用历史响应重执行并比较语义事件 | 失败/流式轨迹的严格重执行、跨构建兼容；这些轨迹仍可检查与校验 |
| 进化 | 根据生产样本生成新提示词版本，自动排队评测，独立审批后另行发布 | 在线修改模型权重、自动扩大权限、自改测试集、自批自发、保证越用越好 |
| 存储 | AES-256-GCM 内容加密、HMAC 事件链与制品签名、事务更新 | 独立 WORM 存储、掌握主机和密钥的攻击者仍不可篡改 |

服务管理员、配置文件、宿主机及注册的工具实现属于可信计算边界。`readOnly: true` 是代码扩展契约，不是对恶意插件的沙箱。生产配置不会加载研究模式的共享记忆或 RL 写入路径。

租户由凭据解析，不接受客户端覆盖。角色权限按租户划分，**不是同一租户内的用户私有会话系统**：viewer/operator 可查看该租户的运行记录，reviewer 可查评测与治理审计。admin 拥有租户内所有权限，但不能批准自己署名的版本。生产上应将作者、审批者、发布者分配给不同人员；仅换 actor 名称不能构成人员独立性。

## 2. 启动

要求 Node >=22.14，建议使用已维护的 22/24 LTS；pnpm 9。`better-sqlite3` 使用原生模块，安装时可能需要 Python、make、C++ 编译器。

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm -F @veridical/server test:production
```

在受信任的管理工作站生成配置。以下命令参数顺序为：**尚不存在的输出目录、租户、HTTPS 模型 API 基地址、模型名、模型版本标识**。提供兼容 `chat/completions` 的服务。版本字段应对应服务商可锁定的实际版本，而不是随意标记一个会静默漂移的别名。

```text
node packages/server/scripts/create-config.mjs <NEW-directory> <tenant> <https-provider-base-url> <model> <pinned-model-version>
```

脚本创建权限 0700 的目录以及权限 0600 的三个文件：

- `config.json`：数据库位置、模型白名单、令牌哈希、身份角色与有效期。
- `ledger-keys.env`：两个不同的 256-bit 密钥；应转入密钥管理系统，密钥丢失将无法恢复数据。
- `operator-credentials.json`：各角色独立随机令牌，有效期 30 天。分发各自令牌后，安全保管或移除此管理端文件，**不要挂载到服务端容器**。

启动前将 `VERIDICAL_CONFIG` 指向绝对配置文件路径，安全注入 `VERIDICAL_DATA_KEY`、`VERIDICAL_AUDIT_KEY`、`VERIDICAL_PROVIDER_KEY`；不要把值写入仓库、镜像或命令行参数。配置中的 `actor` 应改成实际稳定的人员/服务身份。服务只保存凭据哈希。

```bash
pnpm -F @veridical/server start
```

也可以制作不依赖工作区的 Node 运行目录：`node packages/server/scripts/package-runtime.mjs <NEW-output-directory>`。该步骤复制 frozen-lockfile 安装得到的实际依赖闭包，不重新联网解析版本，附带 `runtime-dependencies.json`。在相同操作系统/架构/Node ABI 的目标环境运行其中的 `dist/server.cjs`；原生模块不能直接跨平台搬运。独立运行目录已通过本机冒烟测试。

默认监听 `127.0.0.1:8787`。仅 `GET /health/live` 不要求认证，`/health/ready` 要求有效令牌；未配置、密钥错误、供应商凭据缺失时启动失败。不要设置 `VERIDICAL_MODE=development`：这会启动无生产隔离保证的研究 API。

## 3. 网络与容器

在 TLS 反向代理后运行，禁止不可信客户端直连源端口。生产 API 不启用 CORS、不信任转发头；代理后应用 IP 限流会聚合为代理 IP，应在代理端补充真实客户端限流。所有请求还受到租户/actor 维度的持久化限流。

提供了 Dockerfile；本轮环境没有运行中的 Docker daemon，**未验证镜像构建与容器启动**。验证前使用已通过测试的 Node 构建产物。计划使用容器时：

1. 构建并扫描镜像，发布时锁定基础镜像摘要与最终镜像摘要。
2. 以非 root 用户运行；启用只读根文件系统、`no-new-privileges`、移除 Linux capabilities、设置 CPU/内存/PID 限额。
3. 仅本地持久卷允许写入，数据库目录归运行用户所有、权限 0700。不能使用 NFS。
4. 配置只读挂载，密钥用部署平台的 secret 注入；只把服务端所需密钥提供给服务。
5. 容器内配置 host 为 `0.0.0.0`、port 为 8787，但宿主机映射只绑定回环或专用代理网络。健康检查默认此端口。
6. 启动前执行完整性检查；滚动升级不是本配置的承诺，按维护窗口停止旧实例、备份、升级。

SQLite WAL 的适用范围见 [SQLite 官方说明](https://www.sqlite.org/wal.html)。多进程写入正确性已有测试，不等于已经完成多实例生产容量认证。

## 4. 任务与故障语义

请求先事务性入队，再异步执行。提交返回 202，使用 job id 查询终态；不要将 HTTP 202 当作执行成功。

- 幂等键按租户唯一；相同键和相同有效请求返回同一个任务，不同请求返回 409。有效请求包含解析后的版本/测试集及凭据指纹；切换版本、测试集或凭据后不应复用旧键。
- 每个会话最多一个排队/运行任务；会话固定版本。发布新版不修改旧会话内容；继续会话与当前部署版本不一致时拒绝。
- 执行有总时限、每步权限检查、5 秒租约和每秒心跳。取消、凭据失效、版本撤回会在后续安全检查处阻断执行；已发出的模型请求可能已产生费用。
- 进程退出会中断本进程的任务；被强杀后，租约/时限到期由后续 worker 标记 `interrupted`。**不自动重试中断任务**；人工查看日志、确认后以新键提交。
- 不合作的异步 provider 也不能在取消后继续向账本写结果。同步阻塞/恶意本地工具不在此保证内。
- 单次输入 8,000 字符；请求体 64 KiB；模型上下文 64 KiB，超限明确失败，不静默丢历史；最多 32 步，模型输出上限可配置；每租户最多 20 个活动任务。
- 默认数据库+WAL 阈值 4 GiB、磁盘空闲保留 256 MiB。达到阈值，新业务及就绪检查返回 507，保留撤回/取消通道；这不是精确磁盘配额，单次写入可有有限超量。

限流、步数和超时限制不等于货币预算。应在供应商账户设置费用上限与告警。容量参数需按真实流量验证后调整。

## 5. 发布、撤回与运行环境变更

版本内容不可覆盖。流程为：草稿 → 固定测试集评测 → 非作者审批 → publisher 显式发布到 production/canary。每次变更含原因并写审计；canary 是调用方显式选择的通道，不是自动流量分配器。

评测至少需要三个不同输入，每例有正向断言，且无执行错误。审批绑定候选摘要、评测证据、测试集、代码构建指纹、配置 releaseId、模型配置、工具版本及执行参数。测试集变更或代码/模型/工具环境变化会使旧审批不再适用。

更换代码后，应保留旧产物与备份，在新环境以新版本号重新评测审批。旧批准版本不能直接重新评测覆写证据。允许明确回滚部署指针到**当前环境下仍获批准**的旧版本；不允许借回滚绕过撤回或环境检查。

测试通过只证明配置的断言通过，不证明业务质量、安全性或统计意义上的提升。套件由 reviewer 管理，生成器不会得到保留测试输入，也不能改套件。长期重复使用同一套件仍存在过拟合风险；需要人工维护独立测试数据和线上观察。

## 6. 备份、完整性与恢复演练

本地管理员命令使用与服务相同的 `VERIDICAL_CONFIG` 和账本密钥，但不需要模型凭据。目标文件必须不存在，拒绝覆盖。

```text
node packages/server/dist/admin.cjs checkpoint <new-checkpoint-file>
node packages/server/dist/admin.cjs backup <new-backup-file>
node packages/server/dist/admin.cjs verify <checkpoint-file>
```

checkpoint 含每个会话的序号、末端哈希和 HMAC 签名。将它保存到**与数据库权限隔离、不可回滚的外部存储**。先取检查点再在线备份；验证备份时，配置副本应指向备份数据库，再执行 verify。定期检查点间的回滚窗口仍然存在；本实现没有自动上传到 WORM 服务。

恢复流程：

1. 停止服务，保留故障数据库、WAL、SHM 和相关日志用于调查；不要覆盖或删除唯一副本。
2. 在新的空目录恢复备份，复制配置并把 database 指向恢复文件，恢复原密钥。
3. 执行 `verify`，并使用与备份匹配的外部检查点；检查 SQLite、事件链、制品、指针及加密任务内容。
4. 确认丢失窗口符合业务 RPO；外部检查点比备份新时，校验失败是预期保护，不能直接忽略。
5. 启动服务。残留 running 任务到租约过期后标记中断，由操作人员决定是否重新提交；不自动重复业务动作。

不要运行中只复制 `.db` 而忽略 WAL。在线备份使用 SQLite backup API。已测试加密备份重新打开、密钥错误拒绝、事务强杀恢复、截断检查点校验；**没有测出你的业务 RPO/RTO**。

事件内容、制品、元数据、任务入参与结果加密；租户 ID、actor、版本键、时间、状态等索引元数据不是全盘加密。HMAC 不抵御掌握密钥的主机管理员；回滚整个数据库及其自带链头，只有独立保存的外部检查点能揭示。

目前没有在线密钥轮换、自动保留期限清理、按字段脱敏和用户级擦除接口。不要承诺特定合规要求；需要这些功能的业务必须先补齐生命周期设计。原始客户数据会按业务调用发送给已配置模型服务，落库加密不代替数据出境或保留策略。

## 7. 可观测性与上线门槛

Fastify 输出结构化请求日志，认证头与正文不写入请求日志，错误响应只含错误代码及请求 ID。审计包括版本/测试集/部署变更、任务状态、拒绝授权、trace 读取、令牌撤销。请求日志仍可能包含路径，应禁止在 URL 传凭据或敏感信息。

`GET /v1/metrics` 为 admin 提供租户任务状态计数、数据库/WAL 大小、磁盘剩余和构建标识；不是完整 Prometheus/SLO 平台。至少监控就绪失败、429/5xx、任务失败/中断、队列积压、磁盘、备份新鲜度和供应商费用。

允许上线前必须由部署负责人确认：真实模型兼容性与评测质量、业务只读工具审查、TLS/secret/访问控制、目标机器负载与长稳测试、隔离备份恢复演练、告警实际送达、数据保留责任人。没有这些环境验收，代码测试通过只能称为**受限生产候选**。
